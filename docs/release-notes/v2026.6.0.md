# v2026.6.0

Additive release: snapshot acceleration and idle-actor passivation.

## API delta (additive — x bump)

`PicoActor.Abs`
- `ActorSnapshot(ulong Version, byte[] Payload)`; `IEventStoreSnapshot` (`LoadSnapshotAsync`, `SaveSnapshotAsync`).
- `ISnapshotableActor` (`RestoreSnapshot`, `ReplayEventsFrom`) — implemented explicitly by `EventSourcedActor`.
- `EventSourcedActor`: `TakeSnapshot`, `RestoreSnapshot`, `OnSnapshotFailed`, `AttachSnapshotPolicy`,
  `IsReplaying` (now protected), `CanBePassivated`.
- `SagaActor.CanBePassivated` (false — waiting for a reply is idle by design).
- `IActorPassivationHost.TryRequestStop(Guid, IActor)`.
- `Actor`: `RequestPassivation`, `LastActivityUtc`, `IsProcessing`, `PendingCount`, `TrackIdleActivity`.

`PicoActor`
- `ActorSystemOptions`: `SnapshotEveryNEvents`, `IdleTimeout`, `IdleSweepInterval`.
- `ActorSystem`: `SweepIdleActorsAsync`, `PassivatedCount`, `ReactivatedCount`.
- `InMemoryEventStore` implements `IEventStoreSnapshot`.

## Wire delta

None. `IEventStore` is unchanged (the snapshot capability is a separate optional interface), and
the event stream format is untouched. Snapshots are acceleration only; history is never truncated.

## Breaking changes

None. Every addition is opt-in and off by default (`SnapshotEveryNEvents = null`,
`IdleTimeout = null`), and `Send`/`AskAsync` keep their documented behaviour.

## Limitations left open

- `SweepIdleActorsAsync`/`PassivatedCount`/`ReactivatedCount` live on the concrete `ActorSystem`,
  not on `IActorSystem`.
- `ActorSystem` is not `IAsyncDisposable`; the idle sweeper stops with `StopAllAsync`.
- Snapshot error-path tests remain partial (`TakeSnapshot` throwing, a non-snapshot store).
- No visibility of a passivated id through `Send`/`AskAsync`: reactivation is explicit (`GetAsync`).
