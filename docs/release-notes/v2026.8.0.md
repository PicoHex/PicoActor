# v2026.8.0

The store read contract is split from the write port: two new public interfaces, and a rebuild
that reads only the tail it replays (x bump: new public API, existing stores keep
compiling).

## Why

One interface carried three audiences. `IEventStore.LoadAsync` is used by the rebuild path **and**
by tools and projections, and it forces every store to produce a `Count`-known,
index-addressable, fully deserialized list. For a snapshot-accelerated rebuild that needs only the
events after the snapshot, that means deserializing the whole stream: 82,367 events / 12 MB on a
chat stream, 13,413 events / 25.4 MB on a session stream, in the production store. The v2026.7.1
zero-copy tail view bought nothing there — `LoadAsync` is still an eager `List.Add` loop — which is
the measured proof that only a cursor can move that cost. Business readers were also looking at an
"events" method on the interface they know as "the store".

v2026.8.0 keeps `IEventStore` exactly as it is (three members, unchanged semantics) and adds the
read port next to it: a store that implements `IEventLogReader` lets a rebuild observe the stream
length **once**, read only the tail, and never materialize the head — while a store that does not
keeps working through `LoadAsync`.

## Content

- **`IEventLogReader`** (new, `PicoActor.Abs`): `GetVersionAsync`, `OpenAsync`, `PeekFirstAsync` —
  the read surface for tools, projections and diagnostics.
- **`IEventCursor`** (new, `PicoActor.Abs`): a forward-only, single-observation cursor —
  `End` (stream length seen by this open, never changes), `Current`, `CurrentVersion` (1-based,
  strictly ascending), `MoveNextAsync`, `DisposeAsync`.
- **`IEventStore`** is unchanged: three members, same semantics. It is the **store author's**
  persistence SPI now — append events, keep them, serve them back; `LoadAsync` stays as the
  runtime's fallback read.
- **`InMemoryEventStore` implements `IEventLogReader`.** `OpenAsync` copies the stream under the
  per-actor gate, so a concurrent `AppendAsync` cannot tear the cursor — the same invariant
  `LoadAsync`'s `ToList()` under the gate provides — and `End` is that copy's count.
- **The rebuild prefers the cursor.** When the store is a reader, `GetAsync` opens at
  `v + 1` (`v` = snapshot version, 0 when there is no usable snapshot), takes the length from
  `End`, drains only the tail and replays it. The rollback guard, the tail length and the final
  `Version` all come from that one open.
- **Fallback unchanged.** A store without the reader rebuilds through `LoadAsync` plus the tail
  view; `FindAggregateIds` and `ResumeInterruptedSagasAsync` use the reader's `PeekFirstAsync`
  when it exists and `IEventStore.PeekFirstAsync` otherwise.
- **Capability discovery is one rule** — `eventStore is IEventLogReader`. No new
  `ActorSystemOptions` slot, no wrapper, no DI change; `PicoActorDiExtensions` registers the store
  as-is.
- **Fixed cursor semantics.** `fromVersion` is 1-based and inclusive; `0` throws
  `ArgumentOutOfRangeException`; a `fromVersion` beyond the end is legal and yields an empty cursor
  whose `End` is the real length. `Current`/`CurrentVersion` throw `InvalidOperationException`
  before the first successful `MoveNextAsync` and after the end. A cursor never yields more than
  `End`; it may yield **fewer** if the stream is truncated or archived while it is open, which the
  rebuild turns into a full replay rather than an exception. `DisposeAsync` is idempotent.
- New conformance and runtime-path tests pin the cursor contract and the four rebuild cases
  (reader-only store, rollback below the snapshot, shrinking stream, vanishing stream).

## API delta (x bump)

`PicoActor.Abs` — two additions:

```csharp
// Read port for tools, projections and diagnostics.
public interface IEventLogReader
{
    ValueTask<ulong> GetVersionAsync(Guid actorId, CancellationToken ct = default);
    ValueTask<IEventCursor> OpenAsync(Guid actorId, ulong fromVersion, CancellationToken ct = default);
    ValueTask<IDomainEvent?> PeekFirstAsync(Guid actorId, CancellationToken ct = default);
}

// Forward-only cursor over one open; End is the length observed by that open.
public interface IEventCursor : IAsyncDisposable
{
    ulong End { get; }
    IDomainEvent Current { get; }
    ulong CurrentVersion { get; }
    ValueTask<bool> MoveNextAsync(CancellationToken ct = default);
}
```

`PicoActor` — one implementation delta, no signature change: `InMemoryEventStore` now also
implements `IEventLogReader` (its `GetVersionAsync` and `OpenAsync` are new public members; the
interface row is new). `AppendAsync`, `LoadAsync` and `PeekFirstAsync` are byte-for-byte the same
members as before.

Nothing is removed and no signature changes, so **every existing store compiles and keeps working
unchanged**; implementing the reader is optional. Because the public surface changed, the packages
move to `2026.8.*`: x+1 means "public API changed" under the dependency policy, so a downstream
consumer floating `<year>.<x>.*` (`PicoActor* 2026.7.*`) will **not** pick this release up.
**Migrate the float band to `2026.8.*`.** Consumers that use `IActorSystem` only need no code
change; store authors need none either (the reader is additive).

`api/*.public.txt` is not pre-refreshed by this change — `scripts/release.ps1` refreshes the
baselines at release time.

### Who moves to which member

| Consumer | Before | After |
|---|---|---|
| `ActorSystem.GetAsync` rebuild | `LoadAsync` + skip | reader `OpenAsync(v + 1)` + `End` guard; fallback `LoadAsync` + tail view |
| `FindAggregateIds` | `IEventStore.PeekFirstAsync` | reader `PeekFirstAsync`; same fallback |
| `ResumeInterruptedSagasAsync` | `IEventStore.PeekFirstAsync` | reader `PeekFirstAsync`; same fallback |
| `InMemoryEventStore` | list store | implements `IEventLogReader` |
| Tools: tail / partial reads | `LoadAsync` | `IEventLogReader` |
| Tools: whole-stream projections | `LoadAsync` | **keep** `LoadAsync` (the full list is their requirement) |
| `JsonRpcStoreBinding` (PicoAgent) | `IEventStore` only | **not** a reader in this change — a cursor needs a new RPC verb; it stays on the `LoadAsync` fallback |
| `JsonlEventStore` (PicoAgent) | eager `LoadAsync` | out of this repository; not a reader in this change (needs P1, below) |

## Wire / storage delta

None. Event streams, snapshot payloads and the snapshot envelope are untouched: no new field, no
new framing, no new verb and no migration step. The cursor is a read-time view over the existing
stream — `End` is a count, not a stored artifact. A store keeps its own on-disk format; the reader
contract says nothing about it.

## Prerequisites outside this repository

- **P1 — a discriminator probe.** A file store's cheap head classification needs
  `bool CanResolveDiscriminator(string typeName)` over the **same** registry `Deserialize` uses.
  That is a **PicoSerDe / PicoAgent.Domain** change, not a `PicoActor` change. Until it exists, a
  file store must deserialize every head line it skips over (as `LoadAsync` does), so its cursor
  benefit is limited to "the head is not retained in the replay list" — real, but not the full
  tail-only cost.
- **File store adaptation** (`JsonlEventStore`) and **`JsonRpcStoreBinding`** are PicoAgent work.
  The binding deliberately stays on the `LoadAsync` fallback; giving it a cursor needs a new RPC
  verb and a wire change of its own.
- The `picohex-actor` skill lives in `picohex-skills`; its read-port text is a separate commit.

## Breaking changes

None for compilation, and none for behaviour of code that only uses `IActorSystem`. Notes:

- **A reader store does not have to serve `LoadAsync` anymore.** If the store is an
  `IEventLogReader`, the rebuild goes through the cursor; a `LoadAsync` that throws is no longer
  reached on that path. `OpenAsync`/`MoveNextAsync` exceptions propagate exactly as `LoadAsync`
  exceptions do today (`GetAsync` does not swallow them).
- **Rollback never throws.** A snapshot whose version is beyond `End`, or a stream that shrinks
  between open and drain (`v + tail.Count != End`), discards the snapshot and replays from version
  1 through a second open. A stream that vanishes between the two opens makes `GetAsync` return
  `default` without calling the rebuild factory.
- **Snapshot semantics are unchanged.** Restoring still happens on the same actor instance; a
  snapshot that cannot be applied still degrades to a full replay; snapshot trigger, retention and
  envelope are untouched.
- **A cursor is a snapshot at open.** Appends after `OpenAsync` may or may not be visible, and a
  racing external append is the optimistic-concurrency path's problem, not the cursor's. Do not
  use one cursor for both "read the stream" and "learn the current length later".
- **`End` is a count, not a version of the last event.** For an empty stream `End == 0`; for `n`
  events the last version is `n`. `OpenAsync(id, End + 1)` is a legal empty read.

## Limitations left open

- **`GetVersionAsync` has no in-repo consumer yet.** It is the tools/diagnostics surface; the
  rebuild path deliberately does not call it, because a second observation would reopen the
  race v2026.7.1 closed. It exists so tools do not have to borrow `LoadAsync` for a count.
- **No `SkipToAsync(version)`.** `OpenAsync(fromVersion)` is the only positioning primitive: a
  member that can silently skip events would make missing events a legal outcome, and no consumer
  needs a ranged skip.
- **`LoadAsync`/`PeekFirstAsync` stay on `IEventStore`.** Removing them is a later x release and
  requires every in-use store to implement the reader first — `JsonRpcStoreBinding` included, or
  its retirement.
- **Tail-only cost is not available to file stores yet.** It needs P1 plus the out-of-repo
  `JsonlEventStore` work; until then their cursor saves the replay list, not the deserialization.
- **Tool migration is partial by design.** Whole-stream projections keep `LoadAsync`; only tail
  and partial reads moved to the reader.
