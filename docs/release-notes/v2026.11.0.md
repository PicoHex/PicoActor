# v2026.11.0

Framework events for the JSONL event store: `EventTypeBindings` lets a stream hold a type outside your
`TEventBase` — the saga terminal events (`SagaCompleted`/`SagaFailed`) first. **x bump**: a new public
type plus a new option property are a new public type surface, so the baseline moves even though every
change is additive.

## Why

`PicoActor.SagaActor` persists its terminal events into the **same** stream as the saga's business
events, in the same batch and the same flush. Those two records are `sealed` and derive from
`IDomainEvent`, not from a consumer's event base — a store typed `JsonlEventStore<TEventBase>` therefore
had no way to encode them: the batch was rejected as a non-`TEventBase` element, so a saga aggregate
could not be stored at all, and the only workaround was to declare a duplicate of a framework type
inside your own base.

v2026.11.0 adds a **routing table** for exactly that case, and keeps it as narrow as possible: a bound
type keeps its own generated serializer, its own wire tag and its own place in one batch; the table
contributes only the knowledge that **this tag means this type**, on the write side and the read side.

## Content

- **`JsonlEventStoreOptions.EventTypeBindings`** (`EventTypeBindings`, default: an empty table). Bind
  on the options instance, **before** the store is constructed:

  ```csharp
  var options = new JsonlEventStoreOptions();
  options.EventTypeBindings.Add<MySealedEvent>("my-tag");   // routing only — see below
  var store = new JsonlEventStore<AppEvent>(root, options);
  ```

  The constructor **freezes and copies** the table (one `FrozenDictionary` per direction), so the append
  and read paths take no lock and a later `Add` is **refused** with `InvalidOperationException` naming
  what froze it, instead of being silently ignored. `EventTypeBindings` itself has no public
  constructor: a table floating free of an options instance would be a registration nothing consumes.
- **The store pre-registers the two saga terminal events**, because those tags are the ones production
  corpora already carry:

  | Binding | Wire tag | Registered by |
  |---|---|---|
  | `SagaCompleted` | `PicoActorSagaCompleted` | the store (`TryAdd`) |
  | `SagaFailed` | `PicoActorSagaFailed` | the store (`TryAdd`) |

  `TryAdd` means an **explicit consumer binding wins** — the defaults never overwrite a tag you chose.
  `RegisteredCount` is every binding on the options instance, consumer and applied defaults alike;
  `FrameworkDefaultCount` is how many defaults were **actually applied** (`0…2`), so a boot check can
  tell "my saga streams are writable as they are" from "something replaced the defaults".
- **A batch may mix base and bound events**: `TEventBase ∪ bound` in one `AppendAsync` call is one
  buffer, one write and one flush — a bound tag never costs a second file, a second pass or an extra
  fsync. That is what makes `SagaCompleted` atomic with the events that produced it.
- **Wire format.** A bound event's line is `{"$type":"<tag>"` immediately followed by its payload
  (byte-level: **no comma, and the payload's opening `{` is dropped**), so a bound line is a JSON object
  whose first member is `$type`. The read side **sniffs the first member only**, case-insensitively; a tag
  it does not recognise **falls back unconditionally** to `Deserialize<TEventBase>`, so a stream that
  carries custom discriminators of its own — or was written before this release — reads exactly as
  before.
- **Registration rules, at the call.** One type has exactly one tag and one tag names exactly one type
  (the same pair again is an idempotent no-op **before the freeze** — a frozen table refuses every `Add`,
  the same pair included); a tag must be non-blank and carry no quote, backslash or control character,
  because it is spliced into the line verbatim.
- **Naming.** A stream whose first event is a bound type is named like any other (its CLR short name;
  `FileNameFormat` unchanged). Under `FileNameFormat.TypePrefix`, a name that belongs to **no**
  registered *type* prefix is a **categorical freedom** of a host, not a defect: `unknown-<id>.jsonl`
  is reachable **by id**, invisible to type enumeration (`ListAggregateIdsAsync` answers for the
  registered prefixes only), is **not** counted `ForeignFormatFiles`, and never triggers the
  whole-directory `InvalidOperationException`. A prefix never contains `-`; two types with the same
  short name already share one prefix, unchanged.
- **A terminal-first saga stream is now writable — and it is the one a recovery sweep has to enumerate
  twice.** A flow whose FIRST event is `SagaCompleted` was refused as a non-`TEventBase` element before
  this release and is an ordinary stream now. Under `TypePrefix` the store names a new one after the
  completion (`SagaCompleted-<id>.jsonl`), while the reference corpus files the same shape under its own
  categorical prefix `unknown` — and `ResumeInterruptedSagasAsync<TSaga>(firstEventType, …)` takes ONE
  `firstEventType`. So a sweep that passes `SagaCompleted` finds the new streams and misses the corpus
  ones, and `unknown` finds exactly the opposite (`ListAggregateIdsAsync("unknown")` answers for the
  corpus stream, `ListAggregateIdsAsync("SagaCompleted")` answers `0` for it). Run both passes, or
  migrate the names.

## API delta

```
PicoActor.EventStore.Jsonl
+ EventTypeBindings                                  (class; no public ctor — the options owns the table)
  + Add<T>(string tag) : EventTypeBindings           where T : class, IDomainEvent
  + RegisteredCount : int                            { get; }
  + FrameworkDefaultCount : int                      { get; }
+ JsonlEventStoreOptions.EventTypeBindings : EventTypeBindings   { get; }  (default: empty)
```

No member was removed, renamed or given a new default: the table is empty on a fresh options instance,
the two framework defaults are seeded by the **store** (one seeding mechanism, one owner), and
`api/PicoActor.EventStore.Jsonl.public.txt` is refreshed by `release.ps1`.

## Behaviour changes

- A construction that refuses an ambiguous binding (a bound type that is also `TEventBase`, or an interface
  base) leaves the options **unfrozen and unseeded** — the offender can be deleted and the same options instance
  reused; nothing was registered and no store exists.

- **A bound event is now writable.** Before, `AppendAsync` refused it as a non-`TEventBase` element;
  with a binding — the saga defaults included — the same call succeeds and the event round-trips, with
  the one `object?` exception named under «Limitations left open» (`SagaCompleted.Result` must be `null`).
- **The bindings are frozen at construction.** `Add<T>` after a `JsonlEventStore` was built over those
  options throws `InvalidOperationException` naming the store instead of being ignored: a store copies
  the table, so a late registration would be a rule that applies to nothing.
- **`JsonlEventStoreOptions` equality and `ToString()` now include the table.** The options type is a
  `record`, so its generated `Equals`/`GetHashCode`/`ToString` pick up the new member — compared **by
  reference**, because the table is a live registry rather than a value. Two option records with
  identical scalars therefore are **not** equal, and `ToString()` prints the member. Nothing in the
  store's behaviour depends on that equality; only code that compares or logs options sees it. `with`
  copies the **reference**, not the table: `options with { … }` yields a clone that shares ONE table —
  frozen state included — with its original, so once the original has constructed a store,
  `clone.EventTypeBindings.Add<T>(tag)` throws and names the *other* store. Construct
  `new JsonlEventStoreOptions()` when you need an independent table.
- **A base that already covers the framework events is refused at construction.** With
  `TEventBase = IDomainEvent` (or any type `SagaCompleted`/`SagaFailed` are assignable to) they would be
  both ordinary and bound events — two routes to one type, hence two possible tags. The constructor
  throws `InvalidOperationException` naming both records and the fix: use your own class base and let
  `EventTypeBindings` carry the framework events. A bound type that is assignable to `TEventBase` is
  refused the same way (one type, one registration).
- **One Info line at start-up, per store.** When the options carry a `Logger`, the constructor appends
  one Info record as its LAST step, verbatim `event type bindings: N registered (M framework-default)` —
  `N` is the frozen table's size and `M` how many of those were the store's own seeds. The line is
  **unconditional**: the two seeds are added inside the freeze itself, so the table can never be empty, and
  a guard on a non-empty table would be a branch no store can reach. It is silent without a logger,
  and a construction that throws attests to nothing (no store, no line). A boot check can match that text
  against the deployment instead of probing the store; nothing else about construction changed.
- **A binding's tag may not already belong to a `[PicoDerivedType]` registration on `TEventBase` — the
  construction refuses it.** The read path asks the bindings **first**, so a collision would decode every
  line the base had already written under that tag as the bound type, losing that event and its members,
  with no error on the line. The constructor therefore probes the base's own polymorphic reader once per
  bound tag and throws `InvalidOperationException` naming the tag, before the freeze is committed: the
  options stay usable, nothing is written, and no silent substitution can happen. `Bnd19` asserts the
  refusal and `Bnd19b` documents the one residual hole (a derived reader that recognises the tag and then
  throws).
- **A bound payload that is not a JSON object is refused before anything is written.** The splice drops the
  payload's opening brace, so `[1,2]`, `42`, `null`, `{` with nothing behind it and `{` followed by blanks
  only would be framed into a line that is not JSON at all. A consumer reaches this shape with one public
  call (`JsonSerializer.RegisterCustom<T>` replaces the top-level writer), so the append throws the store's
  own `FormatException` naming the tag, the bound type and what arrived — no file, no version. "Memberless"
  is decided by the JSON behind the brace (`{}`, `{ }`, `{  }`, `{}\n` all write the tag alone), never by
  the payload's length or by where its brace sits.
- **The new cases are `Bnd18`–`Bnd21`** (`tests/PicoActor.EventStore.Jsonl.Tests/`): `Bnd18`–`Bnd18d` the
  payload guard (non-object, memberless forms, leading whitespace, nothing behind the brace), `Bnd19` the
  tag-clash refusal and `Bnd19b` the residual hole, `Bnd20` a throwing log sink, and `Bnd21` the sniffer's
  whitespace and control-byte classification. They assert the wire bytes, the exception types and the
  absence of any file, version or log line — not wall-clock numbers.
- **Line format: none for anything already written.** A stream of base events is encoded byte for byte
  as before; bound lines are new lines, and a tag-less or custom-discriminator line still takes the
  `TEventBase` path.

## Migration

① **Saga streams need no work.** `PicoActorSagaCompleted`/`PicoActorSagaFailed` are the tags your corpora
   already carry and the ones the store pre-registers — a saga stream is readable and writable as it
   stands, with no rename, no rewrite and no binding to add.

② **Consumers of `PicoActor.EventStore.Jsonl` should move to 2026.11.0** when they want saga aggregates:
   on 2026.10.0 an `AppendAsync` carrying `SagaCompleted` is refused as a non-`TEventBase` element.
   Nothing else changes: the option is additive and its default reproduces the previous behaviour.

③ **Binding your own sealed type** takes two steps, because routing and generation are separate jobs:

  ```csharp
  var options = new JsonlEventStoreOptions();
  options.EventTypeBindings.Add<MySealedEvent>("my-tag");   // 1. routing (this table)
  // 2. a generation point in YOUR assembly: a closed call site
  //    _ = JsonSerializer.SerializeToUtf8Bytes(new MySealedEvent(...));
  ```

   Without the binding the append is refused as a non-base element; without the generation point it is
   refused at **first write** with `InvalidOperationException` naming the serializer that is missing.

Downgrade note: a store on 2026.10.0 cannot **write** a saga stream (the batch is refused) and has no
sniffing at all, so it cannot **read** one either — a terminal line whose `$type` its `TEventBase`
dispatch does not know throws exactly as it did before this release, and that refusal is what v2026.11.0
removes. The new read side is the tolerant one: an unrecognised tag falls back to `TEventBase` instead of
becoming a new failure.

## PicoSerDe known limitation

**The attribute form does not work for a positional record.** `[GenerateSerializer(typeof(T))]` goes
through an attribute pipeline that extracts **members only** and never reads a record's primary
constructor, so it emits `new T()` plus init-only assignments — and a positional record annotated that
way fails to compile with **CS7036** (no argument given for the required parameter) or **CS8852**
(init-only property assigned outside an initializer). Observed on `SagaCompleted`/`SagaFailed` and
reproduced with a record declared inside this package's own assembly.

What works is a **closed call site**: a literal `Serialize`/`Deserialize` invocation with a concrete
type argument somewhere in the assembly that owns the type. PicoJetson's invocation pipeline *does* read
the record constructor and emits a correct deserializer. `FrameworkEventSerializers.Generate()` is this
package's generation point for the two framework events (two `SerializeToUtf8Bytes` + two `Deserialize`
calls, unreachable bodies — nothing calls it, and deleting it breaks every saga stream), and its
registration is process-wide, so a consumer of this package gets both serializers with no wiring of its
own.

`Add<T>(tag)` is then the read/write **routing** for a type the compiler has already seen. This is a
PicoSerDe limitation, not a binding one, and it is the reason "bind and generate" are two steps rather
than one.

## Limitations left open

- **`SagaCompleted.Result` is `object?`, and a non-null value is not supported end to end.** PicoJetson
  2026.13's generated writer emits the member with **no value** (`if (value.Result != null) { }` — the
  property name is written, the value is not), so encoding a completion whose `Result` is non-null throws
  in the serializer and **writes nothing** (no file, no version); the generated reader likewise assigns
  `default!` (`// unsupported ctor param type: any`), so a line that carries a non-null `Result` decodes
  as `null`. `null` — the only shape a **durable store** accepts today — round-trips exactly:
  `MarkComplete(result)` with a non-null result cannot be persisted, because the terminal batch throws in
  the serializer and nothing is written (no file, no version). **Keep `Result` null in a persistent
  store** and put structured data in a business event of your own base. The corpus agrees: **all 2,403
  `PicoActorSagaCompleted` lines in the reference corpus carry `"Result":null`**, and a non-null value in
  a consumer's history could not be read back *before* this release either — this is documented, not
  introduced.
- **One codec, still.** A binding routes; it does not add a second serializer, a second file or a
  foreign-line format. A line the generator cannot decode is still corruption.
- **No alias, no re-tagging.** The two framework tags are permanent wire format: there is no alias table,
  and re-registering a type under another tag writes new lines that the old ones do not share. A
  consumer binding may **replace** a default, and its lines then carry the consumer's tag.
- **Bindings are process-local configuration.** Two stores over one directory that disagree about a tag
  disagree about the meaning of the same bytes; the store cannot detect that — exactly as it cannot
  detect a consumer event type renamed in code.
- **One type, one registration.** A bound type must not be assignable to `TEventBase`, and the base must
  not already cover the framework events; both are refused at construction rather than at the first
  append, because both would give one type two routes.
- **A tag the base declares is refused, not silently won.** A binding whose tag already names a
  `[PicoDerivedType]` registration on `TEventBase` fails at **construction** (see «Behaviour changes»), so
  a construction that succeeds can no longer produce the silent substitution this bullet used to warn about.
  What remains open is narrower and cannot be detected from the public API: the guard asks the base's
  reader, so a derived event whose reader **recognises** the tag and then throws (its own argument
  validation, not a missing registration) looks like an unclaimed tag and is accepted — `Bnd19b` pins that
  hole as documented behaviour. A consumer whose event validates its arguments should give the binding a
  distinct tag.
