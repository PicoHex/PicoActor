# v2026.9.0

A generic JSONL event store, and the store family leaves the core package (x bump: new packages,
one breaking move for consumers of `InMemoryEventStore`).

## Why

`PicoActor` shipped exactly one store, `InMemoryEventStore`, inside the core package; the only
durable store in the ecosystem was PicoAgent's bespoke `JsonlEventStore` (2,157 lines plus a
406-line snapshot partial, with ledger scans, archive/retention, checkpoints and fact scans bound
to that product). No other PicoHex consumer could get durable event sourcing without copying it.

v2026.9.0 adds a **generic** JSONL store and, in the same release, moves the in-memory store out of
the core so a host is not forced to carry a concrete store:

| Package | What it is |
|---|---|
| `PicoActor.EventStore.InMemory` | `InMemoryEventStore` + `AddPicoActorInMemoryStore()`; the core `PicoActor` no longer references it |
| `PicoActor.EventStore.Jsonl` | durable JSONL store: one file per aggregate, snapshots as sidecars, AOT/source-generated serialization via PicoJetson |
| `PicoActor.EventStore.Gen` | a Roslyn analyzer (embedded in the JSONL package) that reports `PICOSTORE001` for an `IDomainEvent` the consumer forgot to register |

## Content

- **JSONL store** (`PicoActor.EventStore.Jsonl`): `JsonlEventStore<TEventBase>` implementing
  `IEventStore`, `IEventLogReader`, `IEventStoreSnapshot`, `IEventStoreEnumerator`. One JSON object
  per line in `<root>/<aggregateId:D>.jsonl`; updates are never allowed to write onto a torn tail
  (the line is truncated back to the last `\n` first); a **terminated** line that cannot be
  deserialized is corruption and throws, an **unterminated** final line is a crash tail and is
  skipped; counting and cursor positioning scan bytes (`End` = the length observed at open, and a
  cursor `MUST NOT` yield more than that even if the stream grows).
- **Snapshots**: `PASJ` + little-endian version/length header + opaque payload, written atomically
  (temp + flush + rename). The store never validates a snapshot against the stream — the runtime's
  rollback guard discards a snapshot past the end. A snapshot rebuild deserializes only the tail.
- **Registration** (the one form): `TEventBase` carries
  `[PicoDerivedType(typeof(Event), "tag")]` for every concrete event. `[PicoPolyformic]` only
  renames the discriminator; `[PicoSerializable]` on a **derived** type does **not** make the base
  writable. An unregistered event fails on the first append with a wrapped
  `FormatException`/`InvalidOperationException` naming the base.
- **DI**: `AddPicoActor()` no longer provides a store. Register one first —
  `container.AddPicoActorInMemoryStore()` or `AddPicoActor(myStore)` — or the `IActorSystem`
  resolution throws `InvalidOperationException` naming the InMemory extension.
- **Analyzer** (`PICOSTORE001`, `Info`): flags an `IDomainEvent` implementation that no
  `[PicoDerivedType]` base lists, so the runtime failure above becomes a compile-time signal.

## API delta

New packages (first baselines are generated by this release):

```
PicoActor.EventStore.InMemory   InMemoryEventStore, AddPicoActorInMemoryStore()
PicoActor.EventStore.Jsonl      JsonlEventStore<TEventBase>, JsonlEventStoreOptions
```

`PicoActor` loses `InMemoryEventStore` (moved, not removed from the ecosystem) and its `Description`
no longer claims to provide it; `PicoActor.Abs` is unchanged. This is an **x** release: downstream
must move its float band (`2026.8.*` → `2026.9.*`) and add the store package reference.

## Wire / storage delta

None for existing stores. The new store's on-disk format is described above; it is **not**
byte-compatible with PicoAgent's current JSONL store (different file names, snapshot header and
skip rules) — see the limitations.

## Breaking changes

- `PicoActor` no longer contains `InMemoryEventStore`: add `PicoActor.EventStore.InMemory` and
  `using PicoActor.EventStore.InMemory;`.
- `AddPicoActor()` no longer registers a default store: call `AddPicoActorInMemoryStore()` (or pass
  an explicit store) before resolving `IActorSystem`.
- `ActorConfig.EventStore.Type = "InMemory"` now means "an `IEventStore` must already be
  registered"; the mapping itself moved to the InMemory package.

## Limitations left open

- **Single process**: two store instances over one directory do not share gates; concurrent writers
  fail with an `IOException` instead of being serialized.
- **`FlushToDisk` defaults to `false`** (OS buffers survive a process crash; power loss may leave a
  terminated garbage line, which is corruption and is not auto-repaired).
- No archive/compaction, ledger/checkpoint/fact scans or multi-process support; those stay
  PicoAgent-specific.
- **PicoAgent adoption is a separate, out-of-repo migration**: it needs a one-way file rename, a
  decision for its second (saga) codec and unknown-`$type` lines, a snapshot rewrite, replacements
  for its ledger/archive features, and explicit acceptance of the fsync default.
- The serializer probe P1 (`CanResolveDiscriminator`) is **not** required by this store: a document
  stream that holds only events treats an undecodable line as corruption. P1 remains the
  prerequisite for PicoAgent's skip semantics only.
