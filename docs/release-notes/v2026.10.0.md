# v2026.10.0

Stream naming for the JSONL event store: `FileNameFormat` adds a second, first-class file layout
(x bump: a new public enum and a new option property — `JsonlEventStoreOptions` gains a member, which
is source-compatible but is a **new public type surface**, so the baseline moves).

## Why

`PicoActor.EventStore.Jsonl` named every stream `<id:D>.jsonl`. That is the cleanest name for the
store, but it is not the name PicoAgent already writes in production: `<type>-<id>.jsonl`, where the
type prefix is what lets a host enumerate its aggregates without opening a single file. Adopting the
generic store therefore used to mean **renaming every stream once**, offline, with no supported way
to run the two layouts side by side and no way to tell a half-migrated directory from a healthy one.

v2026.10.0 makes both layouts first-class. The **line format is unchanged in both modes** — only the
file name differs — so `IdOnly` (the default) reproduces v2026.9.0 byte for byte, and `TypePrefix`
makes a PicoAgent directory readable **as it stands**.

## Content

- **`JsonlEventStoreOptions.FileNameFormat`** (`FileNameFormat`, default `IdOnly`):

  | Value | Stream file | What changes |
  |---|---|---|
  | `IdOnly` = `0` (default) | `<root>/<id:D>.jsonl` | nothing — the v2026.9.0 layout, byte for byte |
  | `TypePrefix` = `1` | `<root>/<type>-<id:D>.jsonl` | the type rides in the name: `ListAggregateIdsAsync` resolves the ids from file names with **zero file opens** |

- **The prefix is fixed at creation**: it is `events[0].GetType().Name` of the stream's first
  persisted event (backtick arity kept), and a later batch whose first event is of another type still
  appends to the name the stream was born with. The store keeps an in-memory `id → type` map, learned
  from one filename pass and completed by every classification pass.
- **Migration without renames**: PicoAgent names its streams `{type}-{id}.jsonl` already, so pointing
  this store at such a directory with `FileNameFormat = TypePrefix` is a **configuration change**.
  Snapshots are keyed by the aggregate id (`<id:D>.snap`), never by the stream's name, so they carry
  over unchanged.
- **Mixed directories are diagnosed, never merged**: entries valid only under the other layout are
  counted (`ForeignFormatFiles`, by NAME and monotonic — it gates the `IdOnly` duplicate guard) and
  reported as **one** Warning per scan. The whole-directory diagnosis counts HISTORIES instead: a
  directory with **zero** configured-format histories and **some non-empty** other-format ones
  (`otherNonEmpty` — a zero-length file is a failed append's leftover, not a history) throws
  `InvalidOperationException` naming both counts, both formats and the ways out — from enumeration,
  construction and the lazy pass alike — while a directory of leftovers stays a silent empty store. An
  append for an id that already holds a non-empty stream in the other layout, or two different
  prefixes, is refused before a byte is written.
- **Default unchanged**: `IdOnly` stays the default, and an `IdOnly` store over a single-format
  directory pays no construction scan, no scan per append, and exactly one lazy pass in its lifetime
  (at the first observation of a stream it does not have).
- **The miss cache serves the READ path only.** A `TypePrefix` miss is remembered — a bounded set of
  4,096 ids, emptied rather than grown past it — and shared single-flight, so a burst of **concurrent
  probes of ONE absent id** shares a single pass, and **repeats of that id** are free; a **different**
  absent id pays a pass of its own. An **append never trusts it**: resolving "no stream" there would
  fork a second name beside a stream an external writer created after the map was built, so an append
  re-scans on a miss, then drops only **its own** entry on success (no global lock, nothing wholesale).
  `NegativeCacheInvalidations` counts exactly those drops — identically `0` under `IdOnly`, which never
  remembers a miss. The price is documented rather than hidden: a *read* may answer "empty" for a stream
  that appeared beside it until the next pass, and a new store instance re-reads everything.
- **A stale map is corrected by the next SCAN**, not by an append: a rival prefix that arrives after
  the map was built is recorded by the next classification pass (an enumeration, or the miss of an
  unknown id), and from then on every append for that id is refused and names both files. No directory
  pass was added to the append path to close that window — it would give back exactly what the map
  buys, on the one path that pays per append.

## Cost model

| | `IdOnly` (default) | `TypePrefix` |
|---|---|---|
| Construction | free — no scan, nothing touched | one filename pass (builds the `id → type` map) |
| `ListAggregateIdsAsync` | one file OPEN per stream (the type is in the content) | **zero opens** — names only |
| Append to an existing stream | free | one `stat` (duplicate guard) |
| Append to a new id | one lazy pass, once per instance | one filename pass — an append never answers from the miss cache |
| Repeated **read** probe of the SAME unknown id | one lazy pass per instance, then latched | free — the miss is remembered (negative cache, 4,096 ids, read path only, single-flight) |
| Empty-batch probe of an unknown id | one lazy pass per instance, then latched | one filename pass per call — an empty batch resolves like a writing append |
| Duplicate guard when the directory is mixed | one directory pass per append | one `stat` per append (ungated) |
| Empty batch | version check only, nothing created | same, but it resolves its path like a writing append |
| Invalidation of the miss cache | never (nothing is remembered) | per ID, on a successful append of that id; no global lock |

### Measured (opt-in harness)

`tests/PicoActor.EventStore.Jsonl.Tests/Performance/FileNameFormatPerf.cs` (`[Test, Explicit]`, not in CI).
4,600 streams × 3 events, one warm-up + median of 5, both formats in one process over two independent
directories (Windows 10.0.26100, .NET 10.0.15, Release, warm OS cache):

| Measurement | `IdOnly` | `TypePrefix` |
|---|---|---|
| `ListAggregateIdsAsync` | **784.2 ms** (min 736.6, max 829.7) | **5.5 ms** (min 4.6, max 9.0) — ≈143× faster, zero opens |
| 2,000 first appends to new ids | — | 4,693.6 ms total (≈2.35 ms per new id) |

Reproduce:

```
dotnet test --project tests/PicoActor.EventStore.Jsonl.Tests/PicoActor.EventStore.Jsonl.Tests.csproj   -c Release --no-build --no-progress -- --treenode-filter "/*/*/FileNameFormatPerf/*"
```

The new-id number is the non-amortizable part of the cost model: each *new* id pays one filename
pass on its first append, so a host that creates thousands of aggregates at boot sees that cost
once per aggregate. Seeding the corpus itself is not part of the measurements.

## Migration

① **Do nothing** (recommended default): `FileNameFormat` defaults to `IdOnly`; an existing directory
needs no change, and the release is a drop-in upgrade apart from the version bump.

② **Adopting a PicoAgent directory**: construct the store with
`new JsonlEventStoreOptions { FileNameFormat = FileNameFormat.TypePrefix }` and point it at the
existing root. **No file is renamed** — the prefixes are already there. Verify with one enumeration:
`ListAggregateIdsAsync(typeof(TEvent).Name)` must return your ids, and `ForeignFormatFiles` must stay
`0`.

③ **Migrating an `IdOnly` directory to `TypePrefix`** (optional, only for the enumeration win): stop
the writers, rename each `<id:D>.jsonl` to `<type>-<id:D>.jsonl` (the type is the concrete type of
the stream's first event — read it, or take it from your own aggregate registry), then start the
store with `FileNameFormat = TypePrefix`. Do **not** run the two layouts in one directory unless you
accept the mixed-directory diagnostics: an id present in both is refused, not merged.

Downgrade note: a `TypePrefix` directory is **not** readable by v2026.9.0 (it sees a foreign name
and enumerates nothing); rename back to `<id:D>.jsonl` before downgrading.

## API delta

```
PicoActor.EventStore.Jsonl
+ FileNameFormat                (enum: IdOnly = 0, TypePrefix = 1)
+ JsonlEventStoreOptions.FileNameFormat   (property, default IdOnly)
```

No member was removed or renamed: the delta is additive, and the **x** bump is for the public type
surface (`api/PicoActor.EventStore.Jsonl.public.txt` is refreshed by `release.ps1`).

## Wire / storage delta

- **Line format: none.** Both modes write the same JSON object per line, the same `'\n'` termination
  and the same `PASJ` snapshot container.
- **Names: opt-in only.** `IdOnly` (default) is byte-identical to v2026.9.0. `TypePrefix` names a
  stream `<type>-<id:D>.jsonl`; the prefix is fixed at creation and the type of a stream is therefore
  part of its identity (a renamed event type answers a different enumeration query — see the spec's
  G7 case).
- **One behaviour change, for a misconfigured root only**: a store pointed at a directory whose
  streams are **all** in the other layout now throws `InvalidOperationException` instead of
  enumerating nothing. That is the fix, not a regression — an empty enumeration in that situation is
  how a history disappears from view.
- **The exception surface also names a broken root and an occupied name**: a root that exists as a
  FILE raises `IOException` (nothing can be enumerated, opened or created there), and a stream NAME
  occupied by a DIRECTORY raises `InvalidOperationException` naming the obstacle — on the read path and
  the append path alike, in both formats. A failed lazy pass (misconfiguration, unreadable root, root
  that is a file) is LATCHED: the same exception is raised by every later observation, the directory is
  never re-scanned, and the only recovery is a new store instance once the directory is fixed.

## Limitations left open

- **Single process** (unchanged): two store instances over one directory do not share gates.
- **No automatic migration**: the store never renames a file, in either direction. Renaming is an
  operator action, and a mixed directory is refused rather than reconciled.
- **`TypePrefix` pays a `stat` per append** for the duplicate guard; the `<id>.jsonl` layout's
  advantage is precisely that it needs none.
- **A read may be stale by one event stream.** A remembered miss (and a map hit) is a fact about the
  map this instance saw: a stream another process creates beside it is found by the next pass, not by a
  probe, and only a new instance re-reads the directory from scratch. An append is never stale about
  whether the id **has a stream** (it re-scans on a miss); a read is.
- **A generic event type keeps its backtick arity** in the prefix (`Wrapper\`1-<id>.jsonl`), because
  the name is `Type.Name`; a file name is not a place to invent a prettier spelling.
