# v2026.7.0

Snapshot payloads carry a state-shape tag (x bump: one new protected member).

## Why

A snapshot is acceleration only, so the framework may always discard one and replay the whole
stream. What it could not do before is tell whether the stored bytes were produced by the
*current* state shape: `TakeSnapshot`/`RestoreSnapshot` is the actor's own contract, and a shape
change that keeps the byte layout (an `int` whose meaning changed) is invisible from the payload
alone. The actor can prove "these bytes look like mine", never "these bytes belong to my current
shape" — so a changed layout reached production and produced a silently wrong aggregate at the
first rebuild.

v2026.7.0 puts a framework-owned tag in front of the payload and refuses a snapshot that does not
carry the current tag. The store contract is untouched: the tag lives **inside** the opaque
payload, so `ActorSnapshot`, `IEventStoreSnapshot`, `InMemoryEventStore` and every store (file
stores outside this repository included) gain the protection with zero code changes.

## Content

- `EventSourcedActor.SnapshotSchema` (new, see the API delta): the state-shape tag. Default
  `null` = no envelope, byte-for-byte today's behaviour.
- Framework-owned envelope, written only when the actor declares a tag:

  ```text
  offset 0..3  'P','A','S','1'   magic, 4 bytes (container version, never changes)
  offset 4     schemaLen         1 byte, 0..255 (UTF-8 BYTE count)
  offset 5..   schema            UTF-8 bytes
  rest         actor payload     exactly what TakeSnapshot() returned
  ```

- Restore compares the stored tag with the current one (`StringComparison.Ordinal`) and applies
  the payload only on a match. Every other case rejects the snapshot and replays the full
  stream: a different tag, an enveloped payload read by an actor whose tag is now `null`, an
  untagged payload read by an actor that declares a tag, and a truncated envelope.
- The rejection is an `InvalidOperationException` thrown from `ISnapshotableActor.RestoreSnapshot`;
  the existing `ActorSystem.RestoreOrReplayAsync` catch turns it into a warning plus a full
  replay, so no command and no caller sees a new failure mode.
- `""` is a **real** tag (`schemaLen = 0`); only `null` opts out. Both sides test `is null`.
- A tag longer than 255 UTF-8 bytes writes no snapshot at all and is reported once per trigger
  through `OnSnapshotFailed` (an `InvalidOperationException` mentioning `255`); the command itself
  still succeeds.
- Writing the tag, its encoding and the wrap all run inside the snapshot failure scope: a throwing
  `SnapshotSchema` override cannot turn an already-persisted command into a failed `AskAsync`.

## API delta (x bump)

`PicoActor.Abs` — one addition, `EventSourcedActor`:

```csharp
// State shape changed? Bump the tag. Changing it invalidates older snapshots.
protected virtual string? SnapshotSchema => null;
```

Nothing is removed, no signature changes, no behaviour change for actors that do not override it.
Because this is a new **protected** member, the packages move to `2026.7.*`: x+1 means "public API
changed" under the dependency policy, so a downstream consumer floating `<year>.<x>.*`
(`PicoActor* 2026.6.*`) will **not** pick this release up. Migrate the float band to
`2026.7.*` to receive it. Recompilation and code changes are not required — the addition is
opt-in and its default is inert.

`PicoActor` and the stores: no delta.

## Wire / storage delta

None at the `IEventStoreSnapshot` level: the payload stays `byte[]`, the envelope is inside it.
What changes on disk is the payload of an opting-in actor, and only for snapshots written after
the upgrade. Event streams are untouched — history is never truncated and the trigger stays
event-count based.

## Breaking changes

None for existing code. Behavioural notes for actors that opt in:

- **Two deploys are required over one store.** (1) Ship this binary with `SnapshotSchema` still
  `null` on **every** node and confirm full rollout; (2) only then declare the tag. A single
  deploy that both ships the reader and declares the tag cannot be rolled back safely: an old
  node reads a new enveloped payload as **raw bytes without an exception** (e.g.
  `BitConverter.ToInt32` happily returns `PAS1` as a number) and restores a wrong aggregate.
- **Changing the tag invalidates every stored snapshot once.** That is one full replay per
  aggregate; normal speed returns after the aggregate flushes another `SnapshotEveryNEvents`
  events. A rejected snapshot is not deleted (`IEventStoreSnapshot` has no delete) — it is
  overwritten by the next snapshot, so a low-traffic aggregate replays in full on **every**
  rebuild until it crosses the threshold again.
- **Declare the tag as a type-level constant.** The rebuild instance reads its own value; a
  per-instance tag that differs between the writing actor and the rebuild silently degrades
  every recovery to a full replay, with only a warning as evidence.
- `ISnapshotableActor` implementations outside `EventSourcedActor` get no envelope handling (none
  exist in this repository); they would have to unwrap by hand.

## Known collision: a legacy payload that starts with `PAS1`

A raw payload whose first four bytes happen to be `PAS1` is indistinguishable from an envelope.

- Shorter than 5 bytes: read as "no envelope", applied by a `null`-schema actor as before.
- 5+ bytes: rejected — as a truncated envelope when the length byte exceeds the remaining bytes,
  as a tag mismatch otherwise.
- For a **`null`-schema actor** that is a rejection on every rebuild with no self-heal (its own
  new snapshots are raw too). Declaring a schema is the way out: the first enveloped snapshot
  then matches.
- For a tag-declaring actor it is the normal rejection path: one full replay, then self-heal at
  the next threshold.

## Known cost: an oversized or non-round-tripping tag

- A tag over 255 UTF-8 bytes is a **build-time defect** (it is a type constant): snapshots stay
  off for that type and the failure repeats at every threshold. Expect the log noise; it is not
  transient.
- A tag containing a lone surrogate never round-trips (`Encoding.UTF8` replaces it on encode), so
  it will always mismatch. Keep tags plain ASCII/UTF-8 text.
- One O(payload) allocation per snapshot write (the wrap), amortized over `SnapshotEveryNEvents`
  events.

## Limitations left open

- `SnapshotSchema` protects the **shape tag only**. Bytes that are neither a valid envelope nor the
  current shape (silent corruption of a same-version payload) are still not diagnosed.
- No snapshot retention: one snapshot per aggregate, the newest overwrites, no delete.
- The `PAS1` collision above is documented, not detected.
- Rollback of a tag-declared deployment requires reverting the tag first, then the binary
  (see the two-deploy note).
