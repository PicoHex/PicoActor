# v2026.11.3

Patch release. **No public API change** (`api/` baselines untouched) — this ships a packaging change and the
build plumbing behind it.

## Content

- **Multi-targeting `net10.0` and `net11.0`.** Every packable project (`PicoActor`, `PicoActor.Abs`,
  `PicoActor.EventStore.InMemory`, `PicoActor.EventStore.Jsonl`) now ships **two** `lib/` asset groups, so a
  consumer on .NET 11 gets a `net11.0` build instead of falling back to the `net10.0` one. The
  `netstandard2.0` source-generator packages are unchanged.
- **`global.json` no longer pins an SDK.** The target framework declares the floor; a pin would have to be
  bumped on every SDK move and would make the repository refuse to build on a newer SDK than the pin.
- **CI installs SDK 11** so the `net11.0` leg can build; the test matrix therefore runs **both** target
  frameworks (400 cases each: 214 + 51 + 19 + 113 + 3).

## Compatibility

- Nothing in the API, the wire format, the file naming or the store's behaviour changed in this release.
- Consumers that install this package on .NET 10 get byte-identical assemblies to 2026.11.2 (same source, same
  generator, `net10.0` assets).
- `PicoJetson` stays at **2026.14.0** (the `object?` fix from 2026.11.2 is unchanged).

## Verification

`dotnet build PicoActor.slnx -c Release` — 0 warnings, 0 errors; `dotnet csharpier check .` — clean;
tests green on both `net10.0` and `net11.0` (214 / 51 / 19 / 113 / 3 per framework).
